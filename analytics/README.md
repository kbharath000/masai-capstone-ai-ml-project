# Analytics — Titanic EDA + Predictive Modelling

An end-to-end analytics pipeline on a classic customer/passenger-style dataset: profile it,
clean it, tell its data story visually, then train, compare, tune, and persist predictive
models on it.

## Folder structure

    /analytics
        eda_analysis.py               EdaAnalysis: profile, clean, and visualize the dataset
        predictive_modelling.py       PredictiveModelling: train/compare/tune/persist models
        titanic.csv                   committed offline-fallback copy of the dataset
        models/best_classifier_pipeline.joblib   the saved, reloadable winning pipeline
        1_survival_by_sex.png         }
        2_survival_heatmap.png        } regenerated by eda_analysis.py's multivariate_analysis
        3_age_distribution_box.png    } (savefig calls are module-relative, so they always
        4_fare_vs_age_scatter.png     } land here regardless of the working directory)
        univariate_analysis.png       static chart assets (age/fare histograms + box plots)
        corre_matrix_heat_map.png     static chart asset (correlation heatmap)

## Install / run

From the repo root, with the project's dependencies installed (`pandas`, `seaborn`,
`matplotlib`, `scikit-learn`, `imbalanced-learn`, `joblib` — already in the root
`requirements.txt`):

    pip install -r requirements.txt
    python -m analytics.eda_analysis
    python -m analytics.predictive_modelling

`eda_analysis.py`'s `write_sns_titanic_to_csv` reuses the committed `titanic.csv` if present
(it is — no network call needed) and only falls back to `seaborn.load_dataset` if that file is
ever deleted. Everything below was produced by running both commands above end to end just
now, from this exact code and this exact committed CSV.

**Note on a bug fixed while moving this module:** `predictive_modelling.py` used to import
`Pipeline` from `imblearn.pipeline` and then immediately re-import it from `sklearn.pipeline`,
silently shadowing the first with a version that can't accept SMOTE's resampling step —
`compare_imbalance_handling` crashed as soon as it built the SMOTE pipeline. `imblearn.pipeline.Pipeline`
is a drop-in superset that also works for the plain sklearn pipelines used everywhere else in
this file, so the fix was simply removing the duplicate `sklearn.pipeline` import. Every number
below is from that fixed version actually running successfully end to end.

## EDA: written interpretation

**Cleaning.** Of the loaded columns, `age` (19.87% missing) was median-imputed, `embarked` and
`embark_town` (0.22% missing each) had their few missing rows dropped, and `deck` (77.22%
missing) was dropped entirely — following a threshold rule (drop rows <5%, impute 5-30%, drop
column >30%).

**Univariate — outliers (IQR rule, on the cleaned/imputed data).** Age: 65 outlier points
outside [2.50, 54.50] years. Fare: 114 outlier points outside [-26.76, 65.66]. Fare central
tendency: mean $32.10 > median $14.45 > mode $8.05 — the classic signature of a heavily
right-skewed distribution (a long tail of expensive fares pulling the mean well above the
median and mode).

**Bivariate — survival by sex and class.** Female survival (74.04%) was nearly 4x male
survival (18.89%), and survival fell monotonically with class: 62.62% (1st) > 47.28% (2nd) >
24.24% (3rd). Crossing the two shows they compound rather than substitute for each other:
1st-class women survived at 96.74% and even 3rd-class women still cleared 50.00%, while men
never rose above 36.89% (1st class) and 3rd-class men bottomed out at 13.54% — sex was the
dominant factor, with class acting as a strong secondary multiplier within each sex.
**Correlation matrix** (`corre_matrix_heat_map.png`): the two strongest pairs are `pclass`/`fare`
(|r| ≈ 0.548, negative — class 1 is numerically smallest but priciest) and `sibsp`/`parch`
(|r| ≈ 0.415, positive — passengers with siblings/spouses aboard tended to also have
parents/children aboard, i.e. they traveled as family units).

**Multivariate — the four charts** (`1_survival_by_sex.png` .. `4_fare_vs_age_scatter.png`):
chart 1 restates the sex gap as a bar chart; chart 2's heatmap shows the class x sex
interaction from above visually; chart 3 shows survivors and non-survivors have a similar
median age (~29) but survivors skew slightly younger overall, consistent with a "children
first" effect at the lower tail; chart 4 (fare vs. age, log-scaled fare, colored by survival)
shows high-fare passengers survived almost regardless of age, while the low-fare/older cluster
at the bottom-right is where casualties concentrate most heavily.

**Standardization check.** Z-scoring `age` and `fare` moves both to mean 0.0 / std 1.0 exactly
by construction — included as a sanity check that the transform was applied correctly, not as
a finding about the data itself.

## Model comparison table

Stratified 75/25 split (`stratify=survived`, since the EDA found survival imbalanced at
~61.75%/38.25%) so both splits preserve that ratio (train: 61.71%/38.29%, test: 61.88%/38.12%).

| Model | Accuracy | Precision | Recall | F1 Score | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression | 0.7713 | 0.7237 | 0.6471 | 0.6832 | 0.8088 |
| Decision Tree (depth 3) | 0.7892 | 0.7317 | 0.7059 | 0.7186 | 0.8223 |
| Random Forest (100 trees) | 0.7848 | 0.7284 | 0.6941 | 0.7108 | 0.8336 |

### Class imbalance handling comparison (Random Forest)

| Variant | Precision | Recall | F1 Score |
|---|---|---|---|
| Baseline (no handling) | 0.7284 | 0.6941 | 0.7108 |
| Weighted (`class_weight='balanced'`) | 0.7195 | 0.6941 | 0.7066 |
| SMOTE (train-fold only) | 0.6977 | 0.7059 | 0.7018 |

The unmodified baseline had the best F1 here. Random Forest's own bagged, per-tree bootstrap
sampling already copes reasonably well with this dataset's mild ~62/38 imbalance, so explicit
rebalancing mostly trades a little precision for a little recall rather than improving overall
performance on this data.

### Random Forest hyperparameter tuning (GridSearchCV, 5-fold, scored on F1)

- Best parameters: `max_depth=10`, `max_features='sqrt'`, `n_estimators=100`
- Out-of-bag (OOB) score of the best estimator: **0.8318**
- Tuned test-set metrics: Accuracy 0.7937, Precision 0.7532, Recall 0.6824, F1 0.7160, ROC-AUC 0.8338

### Regression side-task: predicting fare

A Linear Regression predicting `fare` from `pclass, age, sibsp, parch, sex, embarked`
(`pclass` is included here even though it wasn't used for survival classification, since the
EDA correlation matrix found it the strongest linear correlate of fare):

| MAE | RMSE | R² | Adjusted R² |
|---|---|---|---|
| 19.98 | 38.46 | 0.357 | 0.339 |

**Heteroscedasticity conclusion:** the residual plot shows heteroscedasticity (correlation
between `|residual|` and predicted fare ≈ 0.338) — residual spread visibly fans outward as
predicted fare rises rather than staying in a uniform band. This matches the EDA finding that
fare is heavily right-skewed (mean $32.10 > median $14.45 > mode $8.05, with outliers up to
$512.33): the model under/over-predicts far more for high-fare, mostly first-class passengers
than for low-fare ones, so OLS's constant-variance assumption is violated here.

## Final model comparison

Classification and regression metrics are on different scales/units and are **not** directly
comparable to each other — shown as two separate groups evaluating two different targets.

**Group 1 — Classification (`survived`), 0-1 scale:**

| Model | Accuracy | Precision | Recall | F1 Score | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression | 0.7713 | 0.7237 | 0.6471 | 0.6832 | 0.8088 |
| Decision Tree | 0.7892 | 0.7317 | 0.7059 | 0.7186 | 0.8223 |
| Random Forest (Tuned) | 0.7937 | 0.7532 | 0.6824 | 0.7160 | 0.8338 |

**Group 2 — Regression (`fare`), £ units for MAE/RMSE, unitless (≤1) for R²/Adjusted R²:**

| Model | MAE | RMSE | R² | Adjusted R² |
|---|---|---|---|---|
| Linear Regression | 19.98 | 38.46 | 0.357 | 0.339 |

## Final recommendation

**Deploy the Decision Tree model.** It has the highest F1 score (0.719) of the three
classification candidates, with precision 0.732 and recall 0.706, and a ROC-AUC of 0.822
indicating good separation between survivors and non-survivors. It came out ahead of both the
GridSearchCV-tuned Random Forest (F1 0.716, despite a strong 0.832 OOB score) and the Logistic
Regression baseline (F1 0.683) in this run, making it the most defensible choice for deployment
on the current data. The fare Linear Regression (R² = 0.357) is a separate side task on a
different target and is not itself a deployment candidate for survival prediction.

## Saved pipeline

The recommended model's complete pipeline (preprocessing `ColumnTransformer` + fitted
classifier, as a single pipeline object) is saved with `joblib.dump` to
`analytics/models/best_classifier_pipeline.joblib`. `predictive_modelling.py`'s
`save_and_verify_pipeline` also reloads it with `joblib.load` in the same run and confirms the
reloaded pipeline reproduces identical predictions to the in-memory one on raw,
unpreprocessed sample rows (`Reloaded pipeline matches original: True`) — so the saved
artifact is usable end-to-end on new data without re-running any preprocessing by hand.
